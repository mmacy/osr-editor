## [Unreleased]

### Fixed

- Two rows in the area inspector no longer overflow the panel that holds them ([#45](https://github.com/mmacy/osr-editor/issues/45)). Both were found while photographing the content cards for the guides, which is how a defect that had been in every trap since the builder shipped finally got measured. The trap builder's **Condition**, **Duration**, and **Unit** sat on one unwrapping row, and a `<select>` sizes itself to its widest *option* rather than to its value — so `lycanthropy_incubation` made the condition select 188 pixels wide on every trap regardless of what was selected, the row overhung its own card by 19 pixels, the 384-pixel inspector overflowed with it, and the **Unit** select's right edge landed 6 pixels past the window. The panel grew a horizontal scrollbar and nothing said so; setting a condition's unit meant dragging the inspector sideways to find the control. The condition select now takes what the row's fixed fields leave and truncates the longest condition's readout — the dropdown still shows every name in full — so the row fits at any panel width, in a room trap and in a treasure cache's trap alike. The valuables row had the same shape and a worse consequence: five controls on one line left the name — the row's only free-text field, and the one that says whether the thing is an amber bead or a silver circlet — 44 pixels, about three characters. Constraining the other four could not have bought it more than about nine, since a select sized to `jewellery` and two number inputs already at four and five digits have nothing to give, so the row is two lines now: the name takes a full line at 265 pixels, and the kind and the two numbers sit beneath it with the numbers captioned `gp` and `coins`, which also ends their career as a pair of anonymous boxes. The captions are decorative — each field's accessible name is unchanged.

- A feature's contents are offered on treasure caches only ([#35](https://github.com/mmacy/osr-editor/issues/35)). **Items**, **Coins**, and **Valuables** rendered on every feature kind while only the cache's trap was gated, so an author could fill a construction trick or a custom feature with 500 gp and a longsword, save it, validate clean, and publish — and the party could never take any of it, because osrlib's take and inspect handlers reject any feature whose kind isn't a cache. Nothing in the editor said so and no diagnostic mentioned it. The three editors now follow the trap and appear on a cache alone, and changing a cache to another kind clears the contents along with the trap in the kind change's own batch — one undo step, and undo is the way back, the same recovery the trap has always had. A feature that *arrives* carrying contents on a kind that cannot hold them keeps every one of them — an incoming document is never rewritten behind the author's back — and says so, naming what's there, because hiding the fields would otherwise hide contents that still sit in the document and still publish; setting the kind back to **Treasure cache** brings them into view to edit or remove. The **Kind** select also stops rendering raw enum values: its options read **Treasure cache**, **Construction trick**, and **Custom** over the unchanged `treasure_cache`, `construction_trick`, and `custom` the document carries.

- The trap builder no longer offers a trigger that never fires ([#34](https://github.com/mmacy/osr-editor/issues/34)). The **Trigger** select offered `enter` and `open` on every trap, and neither was a free choice: a room trap set to `open` never springs at all — osrlib's room-trap check returns early unless the trigger is `enter`, and an area has nothing to open — while on a treasure trap the field is inert, since the cache-open path springs the trap and never reads the trigger. So an author who set a room trap to `open`, a reasonable thing to try for a trap on the door into a room, got a trap that was authored, saved, linted clean, and dead. The trigger now follows the kind the way the kind already follows where the trap lives: a room trap shows it as read-only text, and a treasure trap doesn't show it at all. What a room trap shows is the document's own value rather than the one it ought to have, so the traps this bug already produced are not stranded by the fix: a room trap carrying anything but `enter` says outright that it never springs and offers **Set the trigger to enter**, one patch and one undo step. Nothing is repaired silently on open — an untouched trap is left exactly as the file has it.

- The treasure preview now names the magic items it rolled ([#36](https://github.com/mmacy/osr-editor/issues/36)). The preview route had been resolving every sampled item's template id to its catalog name and returning it with the quantity and charges all along; the panel printed `1 magic` and threw the rest away — so the preview stayed silent about the one thing most likely to decide whether a hoard suits a room. Each sampled hoard's summary line now carries the items beneath it, one per row: the catalog name, a leading count only when the roll produced more than one, and the charges in parentheses only for an item that carries a charge count. A hoard that rolled no magic renders nothing extra. Gems and jewellery stay a count — naming three gem values is not the same help as naming a wand. No API change, and the `docs/guides/authoring-aids.md` bullet that promised resolved magic-item names before it was retired in #33 is accurate again.

- Dialogs wrap their long strings instead of scrolling sideways, so the import dialog's converter notes are readable where they are written ([#26](https://github.com/mmacy/osr-editor/issues/26)). Every dialog lays its content out as a grid, and a grid item's automatic minimum size is its min-content width — so the widest unwrappable thing any child contained set the whole dialog's width rather than wrapping inside it. The import dialog is where it showed: one long importer note laid a 905-pixel list out in a 510-pixel dialog and pushed the surface into 443 pixels of horizontal scroll, taking the description, both section headings, and the long-labelled **Importer**, **Source level**, and **Destination dungeon** selects with it. The floor is now zeroed in the dialog primitive itself, so the same trap cannot spring in the blocked-op, stocking-report, conversion, or any other dialog the day one of them renders a long id, path, or error. On top of that the import dialog's selects cap to the dialog's width, and its notes and unresolved-transitions lists wrap and break the ids and cell references no wrap can fit, with room for the same handful of notes as before now that each takes more than one line. A user reading which judgment calls the converter made — the round room squared off to fit the grid, the fabricated transition destination that is a validation error until resolved — reads them without dragging the dialog sideways one line at a time.

- The transition dialog's target-cell picker now selects the cell under the cursor. The picker canvas rendered at a fixed thumbnail size but the dialog's layout stretched it to the dialog's width, while clicks kept mapping through the thumbnail's cell size — so a click landed on a cell roughly twice as far from the origin as the one clicked, and everything past the visible midpoint silently did nothing. Clicks now map through the rendered rectangle, correct at any display size the surrounding layout imposes, and the same fix covers the trap builder's slide destination and the feature cards' cell binding, which share the component. The picker also stops being a blurry field of blobs: it draws with the map's own renderer at device-pixel resolution, so walls, doors, corridors, the entrance, existing transitions, and area keys all read the same in the picker as on the canvas — corridors in particular were invisible before, because the old thumbnail painted area fills only. The dialog caps its height and scrolls instead of pushing its footer past the viewport on tall levels, and when the picked landing cell already carries a transition — or is the departing cell itself — the dialog says so — before, the "create the reciprocal stairs" checkbox stayed checked while the reciprocal was silently dropped, leaving a one-way flight and a `transition_unpaired` finding with nothing connecting the two. Sharing the renderer also puts one judgment in one place: on the main canvas as in the picker, area key numbers now skip below eight-pixel cells, where their nine-pixel minimum font was smearing across neighbouring cells at the farthest zoom.

### Added

- **Fit level**, a map toolbar control beside the zoom buttons, frames the whole level in the viewport ([#26](https://github.com/mmacy/osr-editor/issues/26)). The editor already opened a level fitted, but only ever once: the first pan or zoom replaced that view and nothing brought it back, and **Reset zoom** is a hard 100% at the northwest corner rather than a fit. Zooming in scales about the viewport centre, so on a level whose geometry sits in a corner it walks the map further out of frame — one click now recovers from that. **Reset zoom** is unchanged and deliberately so: its deterministic transform is what the map's cell-coordinate maths is computed from, so the two controls sit side by side rather than one replacing the other.

- Transitions are editable in place: selecting a transition cell offers **Edit transition**, which reopens the dialog prefilled and replaces the flight in one undo step — changing an arrival facing no longer means removing the stairs and rebuilding them from scratch. The dialog also grows typed **X**/**Y** coordinate entry beside the picker (a keyboard path where there was only the canvas), a **Use the source cell** shortcut with the source ghosted onto the target grid — the stacked-stairs case wants the landing directly below the departure — live hover coordinates before the click commits, and defaults that follow intent: the target level starts at the nearest level below (else above), and the kind follows the travel direction until touched. Kind and facing options render as sentence-case labels rather than raw `stairs_down` enum values, here, in the inspector, in the import dialog's unresolved-transitions list, and in the trap builder's slide form; trapdoors and chutes state their one-way rule where the reciprocal checkbox would be.

- Map navigation that works the way a web map does, and two level actions the map chrome was missing ([#31](https://github.com/mmacy/osr-editor/issues/31)). **Zoom is feathered and accelerates**: the wheel and a trackpad pinch now zoom proportionally to the gesture instead of taking a fixed step per event, which is what made a trackpad unusable — a single two-finger swipe fires dozens of wheel events, and each one was spending a whole notch. One mouse-wheel notch still zooms exactly as far as it used to. Pinch is read on its own rate, because macOS delivers it as ctrl-wheel frames of a few pixels each and a whole two-finger spread on the wheel's rate bought about 10%. On top of that the rate **ramps with how hard the gesture is being pushed**, capped at 4×: the opening frames of any gesture stay at the base rate so framing a single room is precise, sustaining it accelerates, and a pause of a fraction of a second returns it to precise. The ramp decays rather than coasting, so nothing keeps zooming after your fingers stop and a gesture can never overshoot where you left it. **Pan** gains a two-finger trackpad drag and a plain left-drag under the select tool (a select drag authored nothing before, so a click still selects — the press only becomes a pan once it moves), joining the middle-click-and-hold and space-drag that already worked, plus a **pan tool** (`H`) that binds panning to a plain left-drag for when holding a chord is the wrong hand. A mouse wheel and a two-finger drag reach the browser as the identical event and only pinch is distinguishable, so the two are told apart by the shape of the scroll, with ctrl/cmd-scroll as an always-zoom escape hatch; feathering is what makes a wrong guess survivable, since a misclassified frame zooms by a few percent rather than a notch. The canvas also stops the browser's back-navigation swipe from eating a horizontal pan. **Remove level** moves out of level properties onto the level row, beside the add control and mirroring the dungeon row above it. **Clear content** strips a level back to its geometry in one undo step — area names and descriptions, encounters, traps, treasure, and features go; the grid, edges, rooms and their cells and keys, entrance, transitions, and wandering monsters stay — for the imported map whose rooms arrive already described. It is composed from the ordinary content ops rather than given an op of its own, so it is one undo step, one revision, and an ordinary reasoned area override per area in a forge-backed project; the dialog counts exactly what it will remove first, and a level with neither content nor keyed areas dims the control and explains itself on hover. A sticky **also remove the emptied areas** option takes the key numbers with the prose, leaving the cells as corridor — the walls and doors are edges, so the map reads the same and you keep the shape without the keying. It replaces the per-field clears rather than following them, so the batch is one op per room instead of five. All four dimmed controls in the map chrome — this pair plus the pre-existing **Remove dungeon** and **Roll stocking** — now carry their reason on a wrapper rather than the button, because a disabled button is neither a hover target nor focusable and the explanation was reaching nobody at the one moment it had something to say. **Roll stocking**'s tooltip in particular could never appear while disabled, which is the only state it had anything to explain.

- Path entry that does not require typing an absolute path from memory ([#28](https://github.com/mmacy/osr-editor/issues/28)). Every field that names a filesystem path — new adventure, open project, the convert dialog's PDF and workdir, import, export, detach, and the osr-web checkout — now carries a **Browse** button onto an in-app directory picker: navigate with home and up, see which directories are already native projects or forge workdirs before opening one, filter to the extensions a field wants, toggle hidden entries, and choose a destination that does not exist yet by typing its name in the picker's own path box. And `~` now expands everywhere a path is named — those eight fields, the conversion lookup, and the CLI's `PATH` argument — resolved once in the request models, so the picker can hand back the short `~/adventures/mill.osr` form rather than a path carrying your account name. The new read-only `GET /api/fs` is the one route behind it; it never validates, landing a browse on the nearest existing directory instead, because the routes that consume a path already own their refusals. Pickers are also **sticky per field**: choosing records the directory the picker was standing in, keyed by the field's own id, so the export picker reopens where you keep exports and the project picker where you keep projects — saved in app config beside the recents list, so it survives a reload and a restart. A remembered directory that has since been deleted needs no special case; the browse walks up to its nearest existing ancestor. Config gains `picker_locations`, capped and shape-validated because the keys come from the client.

- Phase 10 — screenshots in the guides: every published page that describes a UI surface now shows it, in both light and dark, from an automated Playwright capture harness that drives the real CLI and built frontend over the existing zero-network fixtures. Thirty-one shots across the landing page, the quickstart, and all twelve guides, each one an asserted UI state rather than a bare capture — the test proves what is on screen before it fires the shutter. Phase 9 deferred screenshots because "a stale screenshot of a living UI is a lie with a caption", so the gate is the point: a new `screenshots` CI job fails when a documented state can no longer be reached, when a control a shot asserts on is renamed, or when a shot's test is deleted or skipped, and `scripts/check_screenshots.py` holds the docs, the committed images, and the harness's own report to each other in all three directions. It does not compare pixels, and the runbook says so plainly — the app ships system font stacks, so a macOS capture and CI's Linux rendering differ in every text-bearing shot. No committed image carries a real, personal, or machine-specific path: the capture servers run under redirected `HOME`s, the home screen is shot in its genuine first-run empty state, and dialogs whose path fields are not the subject are captured empty. The e2e specs' five duplicated gesture helpers collapse into one shared module along the way, resolving an `edgePoint` that had two incompatible definitions.

## [0.1.0] - 2026-07-24

### Added

- Phase 9 — documentation and release: the documentation site at [mmacy.github.io/osr-editor](https://mmacy.github.io/osr-editor/) (mkdocs-material, deployed from `main` by CI), including the guides grown from the README's per-surface prose and the third-party importer guide phase 8 deferred — its example importer excerpted from tested source, so the documented code cannot drift from code that passes; the release engineering that mirrors the siblings — the tag-driven `release.yml` through trusted publishing, the dist audit with its static freshness check (the wheel and sdist both carry the built frontend, machine-verified), and the fresh-venv install smoke that boots the installed console script and fetches the UI from it; both runtime dependencies now resolving from PyPI as published ranges; and the first PyPI release as `osr-editor` 0.1.0.

- Phase 8 — external map import: the first converter over the `GeometryImporter` seam reads [Watabou's One Page Dungeon](https://watabou.itch.io/one-page-dungeon) JSON export. The source's door *cells* resolve onto the editor's door *edges* (the door cell stays floor, the door lands between it and its direction neighbour), its floor rectangles become the edge set connectivity is made of, its positioned notes key rooms as areas by `ref` and never by array position, its entrance-relative and routinely negative coordinates normalize with one translation, and its boundary doors become the level entrance and a level transition. Every guess, drop, and repair is a note the import dialog renders before anything commits: the portcullis and barred doors mapped onto locked ones, the double door onto an ordinary one, steps onto a plain opening, an unknown door type onto an ordinary door, a rotunda onto its bounding square, the dropped columns, water, and ending line, and the fabricated destination a level transition carries — which is a validation error until the author resolves or drops it, so publish will not pass it by. The dialog grows the metadata adoption phase 2 deferred to exactly this converter: the source's title and story ride the same op batch as the geometry (one undo step), shown only when the source carries the field and differs from the project's own, and off by default. `importers.py` becomes a package — the seam, the import-from-project converter, and the new one, both registered through the same public entry-point group any third party uses. The area-id repair every importer needs moves to the seam and now covers all three ids the create-area op rejects, so import-from-project also renames a slash-bearing area id (with a note) instead of failing the whole batch against a forge-backed project. The committed test corpus is hand-authored synthetic OPD-shaped JSON, original material; no generator code is vendored and no editor code outside the converter knows what One Page Dungeon is.

- Phase 7 — authoring aids: three aids that each apply their results as ordinary, undoable op batches. **SRD stocking** rolls a blank room's contents (or sweeps a level's unstocked rooms in one undo step) through osrlib's stocking procedure — grown in osrlib as an additive release when the editor became its first consumer, so the editor owns only the seeds, target selection, and op assembly. The roll is reproducible from a seeded RNG recorded in the `editor.json` sidecar (a master seed plus per-area PCG64 stream snapshots, decimal-string-encoded for JavaScript safety): re-rolls advance per-address streams order-independently, undo restores the rooms but never rewinds the dice, and the stream keys cascade key-for-key with author notes through every re-keying op and its undo/redo. The stocking report renders each room's contents with honest follow-up badges (special, NPC party with its rolled kind and count, trap design, no-lair-treasure) for the hand-work the SRD leaves to the referee. **Previews** are pure reads over osrlib's generators and tables: sample treasure hoards (letters or the unguarded band, with the basic/expert tier toggle and resolved magic-item names), an encounter's sampled counts, stat table, and per-sample XP, and derive-from-HD in the monster editor (XP, the THAC0/attack-bonus pair, and the save band, closing phase 4's deferral). The **prose assistant** drafts read-aloud area descriptions and adventure hooks through forge's provider seam — absent unless a provider is configured, a synchronous call the client can abandon, token usage shown on every draft, and acceptance entirely client-side (the draft commits as an ordinary batch). A new `KeyedEncounter.hoard` toggle (osrlib's, defaulting on) lets an author express the treasure-absent monster room the SRD rolls. New `POST /api/projects/{id}/aids/{stock,preview,prose}`; every emitted op translates in forge-backed projects, so stocking and accepted prose write reasoned `overrides.yaml` entries and never a workdir artifact. The backend, vitest, and Playwright suites run with zero network — prose replays fixtures recorded through forge's `RecordingProvider`, and the live-provider milestone half is recorded by hand.

- Phase 6 — conversion: the editor is the front door to forge's pipeline. **Convert a PDF** on the home screen prices the run first — forge's `estimate()`, which really preprocesses into the destination workdir (module text is never persisted outside your own project) — and presents the page count, per-stage token predictions, and a rough-cost card as a structural gate: no path reaches a running conversion without passing through it, and declining keeps the rendered workdir, which the home screen lists and the pipeline view resumes. Confirming resumes the chain on a worker thread with per-stage progress polled live, cooperative cancellation that lands on stage boundaries (the stage in flight always finishes, so `run.json` never records an abandoned stage and every cancelled conversion resumes), and forge's own message verbatim on failure; success opens straight into the review queue. A workdir whose conversion never completed now opens into the **pipeline view** — per-stage table, stage picker defaulting to the first incomplete stage, `knob=value` settings, and a regenerate-previews control where the survey and content caches exist but assembly cannot yet run — instead of refusing with a CLI remedy. Open projects gain model-stage reruns from the **Pipeline** panel through a session bound to the project: assembly keeps its synchronous fast path, every other stage runs with progress and cancellation and adopts the re-assembled document, commits pause while it runs, and the undo history survives, replaying corrections against the new caches. **Provider settings** reads the `OSRFORGE_FOUNDRY_*` environment the forge CLI reads, reports per-field values and sources plus Entra availability, and accepts session overrides held in memory only — no credential is ever written to editor config and no API response carries one. New `POST/GET /api/conversions`, `…/run`, `…/cancel`, `…/previews`, and `GET/POST /api/provider`; the conversion suites and the Playwright milestone run with zero network against forge's `FixtureProvider` over vendored minimod recordings.

- Phase 4 — the monster editor: the always-present Monsters section (both project types) stocks `Adventure.monsters` with bespoke templates — create from scratch over a model-valid stock 1-HD seed, or clone-and-modify any catalog monster through the new `GET /api/catalogs/monsters/{id}` full-template route, with the picker's "Create monster…" shortcut starting the same flow from the encounter card; the always-saved detail editor covers the whole `MonsterTemplate` (the AC pair gated by the attack-roll toggle, the hit-dice builder, ordered attack routines, movement modes, saves, morale and alternates, alignment, XP notes, dice/fixed/see-below number appearing, the treasure reference, abilities with typed params, defenses, categories) committing whole-value `set_monster_template` batches; an id introducing a collision with the shipped catalog or another bundled template rejects at commit with an inline rename prompt (foreign documents already carrying one stay editable, the finding navigable to the new `monster:<id>` address); a rename cascades every keyed-encounter line, wandering row, and author note in one undo step; removing a referenced template confirms with the reference count and leaves honest diagnostics. In forge-backed projects the three ops block in place with the detach offer — flow entries open the dialog client-side, and the import dialog's new-level mode returns as a visible choice that does the same (the phase 5 absence retired); the forge nav's resolution entry relabels to "Monster resolution". The small-module fixture bundles a bespoke template keyed in an encounter, putting `Adventure.monsters` under the round-trip, golden, and publish discipline permanently.

- Phase 5 — forge-backed projects: opening an osr-forge workdir assembles it fresh and lands in the review chrome — the review queue over `report.json`'s flags with per-flag dismissal marks, source pages beside the inspector, and forge's SVG previews from the map toolbar; every committed edit translates to a merged, reasoned `overrides.yaml` entry (page-anchored machine drafts until a human composes, the explicit-wall seal for synthesized openings, the growth rule for drawing past the derived extent) and re-assembles through forge's own pure loop, with undo/redo as snapshot pairs of the overrides file and the reason ledger; the corrections panel surfaces the reviewable record with inline reason editing and per-entry removal; the monster-resolution panel offers catalog remaps and printed-notation stat-block patches (exclusive per name); the pipeline panel renders `run.json` per-stage status and token usage with the on-demand playability check (findings wipe on the next change, by forge's design) and the assemble-stage rerun knob; ops with no override kind block in place with the detach offer, and detach writes a provenance-recorded native project with author notes carried over; publish and export use forge's bytes verbatim, so a symlink publish republishes live on every correction. The `editor.json` sidecar grows persisted view state, per-entity author notes with the re-key cascade (both project types), review marks, and the machine-draft ledger; the diagnostics envelope gains the forge tier; and the cross-implementation lint-parity suite runs forge's `check()` beside the editor's lint on the shared fixtures. (Phase 4, the monster editor, is deferred by owner decision.)

- Phase 3 — keyed content: the map-first stocking flow — the right-click stocking menu, hollow/filled key numbers with encounter/trap/treasure glyphs, module-notation hover summaries, the unstocked filter (`F`) and the `[`/`]` key-order walk — over the full content surface: keyed-encounter, treasure, room-trap, and feature cards in the area panel with type-ahead pickers fed by the new `GET /api/catalogs/*` routes (monsters, equipment, treasure types, encounter tables), the composable trap builder (kind pinned by where the trap lives), the inline d20 wandering-table editor seeded from the compiled level-band table, level-scope features, the content op vocabulary (`set_encounter`, `set_trap`, `set_treasure`, `add_feature`, `set_feature`, `remove_feature`), and publish to osr-web (symlink or snapshot into a checkout's `adventures/`, gated on validation only — lint warns, with a confirm).

- Phase 2 — the map editor: the graph-paper canvas with the full geometry tool set (rooms, corridors, walls and doors in every state, areas, entrance, transitions with auto-reciprocal stairs), multi-level and multi-dungeon management with rename/renumber cascades and offender-listing resize, the live structural lint tier (forge's `edge_invalid`, `area_unreachable`, `orphan_cell`, `secret_only_access`, and `transition_unpaired` mirrored exactly, plus the editor-only `area_overlap`) rendered on the map with click-to-navigate down to cells and edges and a one-click fix for invalid foreign edge keys, and the `GeometryImporter` entry-point seam with import-from-project as its first implementation — imported levels land as one undoable op batch.

- Phase 1 — projects and prose: the home screen (recents, new adventure, open by path, `osr-editor PATH`), native project create/open with the `editor.json` sidecar, the document service (atomic op batches with revisions and 409 stale-revision safety, bounded undo/redo, always-saved persistence), live content-validation diagnostics with click-to-navigate addresses, the adventure/town/hooks/wandering forms in the pencil-palette design language, the open-time fidelity warning for documents a newer osrlib wrote, and export of the stamped document to any path.
- Phase 0 scaffolding: the wired FastAPI + Vite skeleton (`osr-editor` serves the built frontend and `/api/status`), canonical adventure serialization with a committed round-trip golden fixture, the locked ops/revision/diagnostics envelope, the auth dependency seam, the `ProjectStore` protocol with a local filesystem store, and pydantic→TypeScript type generation with a CI drift gate.
