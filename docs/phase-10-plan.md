# Phase 10 plan — screenshots in the guides

Implementation plan for phase 10 of [the osr-editor spec](spec.md): the published guides gain screenshots of the real editor, captured by an automated Playwright harness whose failure is a CI failure. The milestone is a reader who has never launched the editor seeing every surface the guides describe, with a structural gate that fails when a documented state can no longer be reached.

Phase 9 deferred exactly this, and named both the trigger and the mechanism: *"a stale screenshot of a living UI is a lie with a caption, and the revisit trigger is named (a 1.0 site, or evidence readers bounce without them); if that trigger fires, Playwright already automates the capture"* (`phase-9-plan.md:31`). The owner has fired the trigger. That deferral is not relitigated here — it is honored, and the honoring is precise about its own limits (work item 5): what CI proves is that every documented state is still reachable, and still named as **the shot's own assertions** describe it. What CI does not prove is that the committed pixels still look like today's UI, nor that a shot's assertions match the prose beside it. Overclaiming either would reproduce the very dishonesty phase 9 was guarding against, so the limits are stated here, in work item 5, in the runbook, and nowhere softened.

Like phase 9, this phase adds no editor behavior, and unlike phase 9 it adds no packaging surface: its deliverables are a test harness, a check script, one CI job, and prose.

Nine research facts shape this plan more than any others, each verified against this tree rather than recalled:

1. **`strict: true` already fails the docs build on a missing image — verified empirically (2026-07-24).** Appending `![missing shot](assets/nope.png)` to `docs/index.md` aborts `uv run mkdocs build --strict` with *"contains a link 'assets/nope.png', but the target is not found among documentation files."* The site's `validation:` block (`mkdocs.yml:59-68`) makes every unresolved reference an error. A deleted or renamed screenshot therefore cannot reach the published site, and the existing **docs** job (`ci.yml:156`) is already that gate — this phase adds no configuration to earn it.
2. **Material's `#only-light` / `#only-dark` image suffixes survive strict validation — verified empirically (2026-07-24).** The concern was real: `validation.links.anchors: warn` (`mkdocs.yml:68`) plus `strict: true` could have rejected `shot.png#only-light` as an unresolvable anchor. A probe build referencing both suffixes against real PNGs produced no anchor warning and no abort, and the generated HTML preserves the fragments. mkdocs-material 9.7.7 implements both halves in its own CSS, keyed to the `default`/`slate` schemes `mkdocs.yml:15-24` configures, so the theme-swapped images need **no plugin, no extension, and no `extra_css`**.
3. **The app's dark mode is a pure media query, and the map canvas subscribes to it.** `frontend/src/index.css:32` is `@media (prefers-color-scheme: dark)` with no class toggle anywhere in `frontend/src`, and the map — a `<canvas>` painted through `getContext('2d')` (`map-canvas.tsx:87`) — selects between `LIGHT_THEME` and `DARK_THEME` (`map/render.ts:28,41`) through `usePrefersDark()`, which listens for `matchMedia` change events (`map-editor.tsx:135-148`). Playwright's `colorScheme` emulation drives exactly that media query, so both the chrome and the canvas flip with **zero app changes**. This is what makes the two-theme capture nearly free rather than a feature request against the frontend.
4. **Any shot that renders a filesystem path would publish the capturing machine's paths, and `HOME` redirection alone does not fix it.** `config.py:71` resolves recents through `platformdirs.user_config_path("osr-editor")` with no environment override, and `home-screen.tsx:162,183` renders each recent's full `recent.path`. Redirecting `HOME` relocates that config on macOS (verified: `platformdirs` 4.10.1 returns `<scratch>/Library/Application Support/osr-editor`) and on Linux, but it does **not** make the problem go away, because the path leak is wider than the home screen: **New adventure** renders a destination directory, **Export** a destination file, and the convert dialog a source PDF and a prefilled workdir. Worse, seeding plausible-but-fake recents backfires — `app.py:588` sets `missing=not store.project_exists(entry.path)` and `home-screen.tsx:154-166` renders a missing entry greyed at `opacity-70` under "The directory has moved or been deleted", so curated fake recents would picture three broken projects. Work item 2's capture rules address the whole class, not the one shot.
5. **Every shot test that opens or creates a project mutates shared server state.** `_record_recent` fires on open (`app.py:611`), create (`app.py:636`), detach (`app.py:817`), and both conversion paths (`conversions.py:592,863`), newest-first (`config.py:134`); provider configuration set through `POST /api/provider` is process-global (`aids.spec.ts:85-88`, `conversion.spec.ts:129-133`). Two theme projects running the same specs against one server would race on both. The harness pins serialization and a dedicated pristine server rather than hoping.
6. **The fixtures for every hard surface already exist and are zero-network — with two caveats that change the shot list.** `tests/fixtures/forge_workdir` raises twelve flags across five areas of *The Millstone Warrens* (`forge.spec.ts:16,49-50`), and `tests/assets/prose` holds recorded exchanges fingerprinted against a *"Stocking demo"* project with a blank area 1 (`aids.spec.ts:9-10`). The caveats: **(a)** `forge_workdir`'s source pages are 480×400 white PIL rectangles of default-font text (`tests/generate_forge_workdir.py:291-297`), so the forge guide's flagship "correction against the printed page" shot must come from `tests/assets/minimod`'s real 1275×1651 pdfium renders (CC0, `tests/assets/README.md:9-14`) rather than from the workdir that supplies the queue; **(b)** the conversion specs configure `kind: "fixtures"` and the pipeline view renders `FixtureProvider` (`conversion.spec.ts:173`), a provider the spec's own comment says "no end-user affordance exists for" (`conversion.spec.ts:126-128`) — so the pipeline shot is clipped to the stage table, never the provider strip. The "no network in tests" invariant holds unchanged throughout.
7. **`tests/assets/opd/nominal.json` produces only provenance notes; `torture.json` is the one that teaches.** `test_importers_watabou.py:144-156` is named `test_the_nominal_fixture_imports_with_only_the_provenance_notes`. The import dialog's judgment-call notes — the portcullis, the rotunda, the fabricated transition destination — come from `torture.json`, asserted at `map.spec.ts:212,226-229`. The import shot uses `torture.json`.
8. **The e2e helpers are duplicated unevenly, and one of them has two incompatible definitions.** `cellCenter` appears four times (`map.spec.ts:51`, `stocking.spec.ts:50`, `monsters.spec.ts:37`, `aids.spec.ts:43`), `drag` three (`map:71`, `stocking:69`, `aids:52`), `createProject` and `openMap` twice each (`map:35,44`, `stocking:35,44`), and `drawRoom` exactly once (`aids.spec.ts:59`). `edgePoint` is the trap: `map.spec.ts:61` and `stocking.spec.ts:59` take two adjacent cells and return their shared edge, while `forge.spec.ts:20` takes one cell and returns its **west** edge — same name, different computation. `aids.spec.ts` inlines its own create flow because it needs the project id from the POST response (`aids.spec.ts:72-81`), which the shared helper must therefore return.
9. **The map view is only deterministic after an explicit reset.** `resetView()` (`map/view.ts:43`) and the **Reset zoom** button pin the transform, and every map-touching spec clicks it before computing coordinates (`map.spec.ts:47,127,135`, `stocking.spec.ts:47`, `monsters.spec.ts:101`, `forge.spec.ts:84`, `aids.spec.ts:93`). A screenshot taken without it captures whatever pan and zoom the preceding gestures left behind.

## Scope

In scope:

- A capture harness under `tests/screenshots/`, wired as Playwright projects in `frontend/playwright.config.ts` with its own servers, pinned viewport, serialized execution, and a light/dark project pair
- The shared helper module fact 8 requires, with all five affected e2e specs migrated onto it
- The 26-shot list below, each one an asserted UI state whose path-bearing fields are curated
- The captured PNGs committed under `docs/assets/screenshots/`, referenced from all ten published pages with Material's theme suffixes
- `scripts/check_screenshots.py` — the three-direction consistency guard (docs↔files↔harness) and the weight budget
- A **screenshots** CI job that runs the harness, type-checks the specs, and uploads the fresh capture as an artifact
- The `package.json` `shots` script, the `AGENTS.md` capture runbook, the phase 10 roadmap entry, and the CHANGELOG bullet

Out of scope (each with where it goes): **Pixel-diff regression gating** — rejected on evidence: the app uses system font stacks only (`index.css:58-59`, *"System stacks only — no bundled webfonts"*), so macOS-captured PNGs and CI's Linux rendering differ on glyph rasterization in every text-bearing shot, and a pixel gate would fail on cosmetic noise while teaching the team to ignore it. Named revisit trigger: if the capture is ever moved to a container that renders identically to CI, byte-comparison becomes viable and this decision reopens in that change's own plan. **Generating the screenshots at deploy time instead of committing them** — the genuine alternative, and it is rejected on three specifics rather than by omission: a clean checkout's `mkdocs build --strict` would fail on every missing image (fact 1 cuts both ways), local `mkdocs serve` would show a broken site to anyone editing prose, and the images would become invisible to code review, which is the only place a human ever compares them to reality. **A mechanical re-capture gate** (failing any PR that touches `frontend/src/**` without touching `docs/assets/screenshots/**`) — rejected as noise: the large majority of frontend changes touch no screenshotted surface, and a gate that is routinely overridden trains the team to override it. The re-capture rule stays a runbook convention and work item 5 is explicit that it is one. **Animated GIFs or video** — unreviewable in a diff, unbounded in weight, no staleness gate; the trigger for reopening is a guide whose prose demonstrably cannot carry a gesture. **Annotated or callout-overlaid images** — an overlay is authored content that drifts independently of the UI beneath it. **Screenshots in the README** — PyPI renders it far from the repository and would need absolute raw-GitHub URLs, a second staleness surface with no gate; the README keeps its phase 9 product-map role. **A walk-mode shot** — the surface does not exist (`backlog.md`). **New editor behavior of any kind, including an `OSR_EDITOR_CONFIG_DIR` override** — fact 4's `HOME` redirect plus work item 2's capture rules make it unnecessary, and the app surface stays frozen as phase 9 left it.

On licensing, stated because a phase that commits fifty-two images of module content into a repository whose licensing page says it ships no game content should say the words: every screenshotted fixture is original or CC0 — `forge_workdir`'s pages are PIL-drawn originals (`tests/generate_forge_workdir.py:291-297`), `minimod` is CC0 vendored from osr-forge (`tests/assets/README.md:9-14`), and `opd/*.json` is hand-authored (`tests/assets/README.md:36-44`). No retail module content is anywhere near the shot list, and `check_dist.py:34` already lists `docs` among the forbidden dist directories, so screenshots can never ride into a wheel or sdist.

### 2. The capture harness

`tests/screenshots/` — a Playwright testDir beside the e2e suite, sharing its helpers and its zero-network posture. `frontend/playwright.config.ts` changes shape:

- The existing project is **renamed** `chromium` → `e2e` (`playwright.config.ts:12`) and gains `testDir: '../tests/e2e'`.
- `shots-light` and `shots-dark`: `testDir: '../tests/screenshots'`, `viewport: { width: 1280, height: 800 }`, `deviceScaleFactor: 2`, `colorScheme: 'light' | 'dark'`, `reducedMotion: 'reduce'`, and — the omission that would have silently defeated the whole design — **an explicit `baseURL` of `http://127.0.0.1:8632`**, because `use.baseURL` is set globally at `playwright.config.ts:11` and a project that does not override it navigates to the e2e server instead.

`webServer` becomes an array of three: the existing e2e server on 8631, unchanged; a **shots server on 8632** where every shot that creates, opens, or converts a project runs; and a **pristine server on 8633**, reached by absolute URL from exactly one spec.

**Both** new servers redirect `HOME` **and `XDG_CONFIG_HOME`** — not just 8632, and not `HOME` alone, because on Linux, where the screenshots job runs, `platformdirs` consults `XDG_CONFIG_HOME` first — into scratch directories the harness's `globalSetup` removes and recreates on every run. *Amendment (implementation): those directories live at `/tmp/osr-editor-shots` and `/tmp/osr-editor-pristine`, not under `frontend/test-results/` as first written. The reason is the invariant above: the editor's backend performs no tilde expansion, so a dialog renders a path exactly as typed, and a scratch root inside the checkout would put `/Users/<name>/repos/osr-editor/...` into every shot of the import and convert dialogs. A generic root outside the tree is what makes the copy-under-scratch rule actually deliver a generic string. Recreating them is `globalSetup`'s job explicitly rather than a side effect of Playwright's `outputDir` cleanup, so the guarantee does not evaporate if the scratch paths ever move again.* "Pristine" means *empty*, never *the machine's real home*: this repository's owner has ten real recents in `~/Library/Application Support/osr-editor/config.json`, including `~/Documents` project names and `/private/var/folders/` temp paths, and a server on 8633 inheriting that would render all ten into the flagship quickstart image while CI — whose `HOME` genuinely is fresh — passed happily and never noticed. The `home-screen` shot therefore asserts the empty-recents state before it captures, so a polluted scratch home fails the run rather than publishing.

Both servers pin `UV_CACHE_DIR` and `UV_PYTHON_INSTALL_DIR` back to the real `~/.cache/uv` and `~/.local/share/uv/python`, because a redirected `HOME` would otherwise send uv looking for its cache and its managed interpreters in the scratch directory. The config computes those from `os.homedir()` and `path.join` — a Node `env:` block performs no tilde expansion, so a literal `~/.cache/uv` would silently create a directory named `~`. Verified: `HOME=<scratch> UV_CACHE_DIR=<real> uv run osr-editor --help` exits 0 against the already-synced project venv. Both entries also carry `reuseExistingServer: !process.env.CI`, matching the existing server (`playwright.config.ts:19`); without it a lingering local server on either port hard-fails `npm run shots` on a port collision instead of being reused.

Fact 5 means recents accumulate the moment any spec creates a project, so `home-screen` is captured against 8633 in its **first-run empty state** — which is also what a reader who just ran `uv tool install` actually sees, making the honest choice and the reproducible one the same choice. No spec pointed at 8633 ever creates, opens, or converts anything.

*Amendment (implementation): Playwright starts every `webServer` entry regardless of which projects run, and `webServer` has no per-project scoping in 1.61.1. Left alone, this change would boot three `uv run osr-editor` processes on every `--project=e2e` run — including the release gate — so the two capture servers are gated behind a `PLAYWRIGHT_SHOTS` environment flag that `npm run shots` and the screenshots job set. An `--project=e2e` run then boots exactly the one server it booted before, and a mistake in the capture environment can never break the shipped artifact's gate.*

Execution is serialized: `npm run shots` and the CI job both pass `--workers=1`, and the config sets `fullyParallel: false`. Fact 5's shared provider state and fact 4's shared recents are not conditions to race against for the sake of a few seconds. The cost is budgeted rather than discovered, and the CI job sets a deliberate 20-minute timeout rather than inheriting a default. *Amendment (implementation): the budget was set from the 60-second timeouts the conversion e2e specs carry, and proved far too pessimistic — a full capture of all 26 shots in both themes runs in about 20 seconds, because the fixture-replayed conversion never calls a model. The timeout stays where it is; it is now headroom rather than an estimate.*

Six rules govern every shot, and the rules are the gate:

1. **Assert before capture.** A shot named `stocking-context-menu` asserts the menu's items are visible before it fires. The capture is the last statement of a test that has already proven the state.
2. **Reset the view before any map shot** (fact 9).
3. **Curate every path-bearing field** (fact 4). A dialog whose empty state is the teaching state — **New adventure**, **Export**, **Publish** — is captured *before* its path fields are filled. Where a path must be visible, the fixture is copied under the capture server's scratch root first — and that root is a **generic absolute location outside the checkout**, because copying alone proves nothing: a scratch home inside `frontend/test-results/` is still a real path carrying the machine's username, which is how the first draft of this rule would have published `/Users/<name>/repos/osr-editor/...` into the quickstart. Two shots need it and both are named rather than left to the rule: the convert dialog's PDF before `estimate-card`, and the One Page Dungeon export before `import-dialog` — the latter because `import-dialog.tsx:205`'s **Source path** field and its `aria-label="Importer notes"` list (`:304`) live in the same dialog, so a shot that shows the notes necessarily has the path in frame. The invariant is checkable and stated as such: **every path visible in a committed image is either an empty-state placeholder or the harness's own fixed scratch root** — never a location that varies by machine or user.
4. **Clip to the subject unless the layout is the point, and never past a 2.5:1 aspect.** *Amendment (implementation): `locator.screenshot()` captures a scrollable panel's entire scroll extent, which for the monster editor is some 4,300 CSS pixels — a hairline ribbon in a docs column and the heaviest file in the set. `shoot()` now clips anything past that ratio to its top, which is the part a caption is ever talking about.* `locator.screenshot()` on the panel, dialog, or menu under discussion; full-window `page.screenshot()` for exactly four shots — `map-editor-hero`, `home-screen`, `project-chrome`, and `map-lint-markers`. This is the weight control and the better image. A full-window shot of a sparse screen frames the viewport to its content rather than publishing half a page of empty paper.
5. **`animations: 'disabled'`, `caret: 'hide'`** on every capture.
6. **Resolve output paths from the repository root**, not the working directory: Playwright's `path` option is relative to `process.cwd()`, which is `frontend/` under CI's `working-directory` (`ci.yml:148`), so the harness derives its target from `test-info.project.testDir` and writes to `<repo>/docs/assets/screenshots/`. The `-light` / `-dark` suffix is derived from `testInfo.project.name`, so a slug is written once per test and the theme pair falls out of the project matrix.

CI's captures overwrite the committed files in the runner's working tree; they are uploaded as an artifact and discarded, never committed by a bot.

### 4. The consistency and budget guard

`scripts/check_screenshots.py` — stdlib-only, `uv run python scripts/check_screenshots.py`, accumulating every failure before exiting, in the idiom of `scripts/release/check_dist.py`. It parses every published `.md` under `docs/` for `assets/screenshots/*.png` references and asserts: every referenced file exists; **every existing file is referenced** by at least one page (the orphan direction mkdocs cannot check); every referenced shot has both a `-light` and a `-dark` twin with the matching Material suffix; every image has non-empty alt text; and the directory stays under the weight budget.

It takes an optional `--produced <manifest>` argument and then asserts the **third direction**: that the slug set the harness produced equals the slug set the docs reference. This closes the hole that would otherwise make the whole gate hollow — deleting a shot's test leaves the committed PNG, the docs reference, and mkdocs all perfectly happy while the shot silently loses its gate forever.

The manifest is load-bearing and the obvious implementation of it does not work. Pointing `--produced` at `docs/assets/screenshots/` is **inert**: the harness writes into that directory, but it arrives from git already holding all fifty-two committed PNGs, so a deleted shot's images are still on disk, still referenced, and the comparison is tautologically green. Instead the harness *reports what it actually ran*: `shoot()` appends `<slug>-<theme>` to `frontend/test-results/produced-shots.txt` — per theme rather than per slug, so a shot skipped under one project only still fails instead of being covered by its twin —, and a Playwright `globalSetup` truncates that file once per invocation. `--produced` reads the manifest, not a directory listing. This also catches `test.skip`, which no directory listing ever can — a skipped shot exits zero and leaves its stale PNG exactly where it was. The screenshots job runs the script in this mode; the docs job runs it without.

The budget is **measured, not asserted**. The implementer runs the full capture once, records the total, and sets the ceiling at the next round number above roughly 1.3× it, with the measured figure written into the script's comment. This matters more than it looks: `.git` is 9.7 MB today, so a careless budget could sanction a screenshot directory larger than the entire repository history. If the measured total exceeds 10 MB, the levers are applied in an order chosen to compose with the file organization rather than fight it: first a per-image ceiling of 400 KB, which points at the specific offenders; then a lossless `oxipng` pass over the directory. Dropping `deviceScaleFactor` for the full-window shots is deliberately *not* the first lever — it is a browser-context option, so per-shot control means `test.use()` at file or describe scope, which would force the four full-window shots into one file and cut across the fixture-cost grouping the sequencing prescribes.

### 5. CI, and what the gate actually proves

`ci.yml` grows a **screenshots** job modeled on **e2e** (`ci.yml:114-153`): checkout, uv, node, `uv sync --locked`, `npm ci`, `npm run build`, `npx playwright install --with-deps chromium`, `npx tsc -p ../tests/screenshots` (its own tsconfig — `tests/e2e/tsconfig.json` is rooted at `tests/e2e` and does not reach a sibling directory, and the shot specs must not become the only untyped TypeScript in the repository), then `npx playwright test --project=shots-light --project=shots-dark --workers=1`, then `check_screenshots.py --produced frontend/test-results/produced-shots.txt`, then `actions/upload-artifact@v4`. The job sets `PLAYWRIGHT_SHOTS=1` so the capture servers start, and a 20-minute timeout per the serialized-runtime budget in work item 2. Ubuntu only, like **docs**.

Three existing call sites must be pinned in the same change, because Playwright's `projects` and `webServer` are config-global and every bare invocation would otherwise start capturing:

- `ci.yml`'s e2e step gains `--project=e2e`.
- **`release.yml:123`'s bare `npx playwright test` gains `--project=e2e`** — without it, tagging a release would capture fifty-two screenshots and let a shot failure block a PyPI publish.
- `AGENTS.md:74` says the release re-runs "all four `ci.yml` jobs"; **screenshots** makes five, and the sentence is amended to name the four it duplicates and to say why the fifth is excluded: the release gate exists to prove the shipped artifact, the screenshots gate proves the docs harness, and `release.yml`'s own strict docs build already fails if any referenced image is missing from the tree being released. `check_screenshots.py` is added to `release.yml`'s docs job for the same reason it joins `ci.yml`'s.

What this gate proves, stated precisely because the phase exists to answer exactly this: a UI change that makes a documented state unreachable, renames a control a shot asserts on, or deletes or skips a shot's test **fails CI** — the last of those only because the harness reports the slugs it actually ran (work item 4), not because the images are on disk. A purely cosmetic change — palette, spacing, typography, an added ninth tool beside the eight a shot asserts — **does not**, and the committed image silently ages. The backstops for that residue are the uploaded artifact, which puts a fresh capture in front of a reviewer, and the runbook rule below. The runbook rule is an unenforced convention in the changelog's class, not a mechanical gate in the generated-types class, and work item 6 says so in those words rather than implying otherwise.

### 6. The docs changes, the runbook, the roadmap, and the changelog

Each of the ten published pages gains its shots inline, where the prose already turns to that surface, in the pattern fact 2 verified:

```markdown
![The review queue listing twelve flags to review](../assets/screenshots/review-queue-light.png#only-light)
![The review queue listing twelve flags to review](../assets/screenshots/review-queue-dark.png#only-dark)
```

Alt text describes the state, not the file; prose stays sentence case. The guides' arguments are not rewritten — screenshots are added to prose that already works, and any sentence a screenshot makes redundant is cut rather than left to say the same thing twice.
