# Phase 8 plan — the One Page Dungeon importer

Implementation plan for phase 8 of [the osr-editor spec](spec.md). Phase 8 ships the first external geometry converter — Watabou's One Page Dungeon JSON export — through the `GeometryImporter` seam phase 2 built, plus the metadata adoption UX phase 2 deferred to exactly this converter. Nothing about the seam changes: the importer is discovered through the `osreditor.importers` entry-point group like any third-party package, and its payload lands as an ordinary op batch — undoable, revision-guarded, immediately linted. Milestone: generate a dungeon at Watabou's generator, import its JSON into a blank project, adopt its title and story, stock and publish it, and play it in osr-web.

Nine research facts shape this plan more than any others, and every geometric claim below was validated against a real current-version export (`version: "1.2.7"`, 75 rects / 41 doors / 9 notes / 24 columns) in addition to a 145-file corpus spanning 1.1.1, 1.2.4b, and 1.2.5 — then re-confirmed against three further fresh 1.2.7 exports (shuffled refs, a backdoor, a type-8 in an ordinary export; every occupancy row exact, every note centred in exactly one rect, rects integer and non-overlapping in all three). First, **doors are cells in OPD and edges in osrlib — this is the central impedance mismatch and it resolves cleanly**. The generator's own `getData()` pushes a bare `{x, y, w: 1, h: 1}` rect for every door *before* pushing the door record, so a door is a full floor cell; the editor's door is an `Edge{kind, door}` between two adjacent cells (`EdgeKind.OPEN|WALL|DOOR`, osrlib `crawl/dungeon.py`). On the 1.2.7 sample all 41 door cells are themselves floor, **no two door cells are adjacent**, and the ahead/behind occupancy table is perfectly clean: interior types (0, 1, 2, 4, 5, 6, 9) have floor on both sides, type 3 has floor ahead and void behind, type 8 has void ahead and floor behind. So the rule is forced and total — the door cell stays floor, the door lands on the edge between the door cell and its `dir` neighbour, and the two boundary types are not edges at all (they are the entrance and a level transition). Second, **floor is not a field; connectivity is the edge set**. `ImportedLevel` carries `width`, `height`, `edges`, `areas`, `entrance`, `transitions` and no cell-occupancy field, because in osrlib's model an absent edge is a wall — the editor's own importer says so in as many words ("an absent edge is already a wall", `importers.py:242`). So "import the map" means: take the floor-cell set as the union of `rects` (verified non-overlapping — 438 distinct cells, zero covered twice), then emit an `OPEN` edge for every orthogonally adjacent floor pair, overridden to `DOOR` where a door sits. Unkeyed floor — corridors, junctions, undescribed rooms — is legitimate and needs no area. Third, **the door enumeration is ten values, not the eight reported in the wild**, and only some of them have a model: 0 open and 2 narrow are `OPEN`; 1 door is a plain `DoorSpec()`; 5 double is a plain door plus a note; 6 secret is `DoorSpec(kind="secret")`; 4 portcullis and 7 barred are `DoorSpec(locked=True)` plus a note naming what the model cannot say; 9 steps is an intra-level elevation change with no editor model, so `OPEN` plus a note; 3 and 8 are the boundary pair from fact one. Fourth, **notes key rooms by centre, and `ref` is not the array index**: `getNotes()` builds `{point: room.center(), symb: String(index + 1), text: room.desc}` — `symb` is the generator's internal name; the field serializes as `ref` in every export, so `ref` is what the reader looks for — and on the sample every one of the 9 notes' `pos` is the exact geometric centre of exactly one rect, 9/9. But the array order is *not* ref order — observed `1, 2, 3, 6, 5, 7, 4, 8, 9` — because `sortRooms` orders by A\* path cost from the entrance, so the importer keys by `ref` and never by array position. Fifth, **coordinates are entrance-relative and routinely negative**: the origin is the entrance, not a corner, and the sample spans x ∈ [−23, 16], y ∈ [−30, 14], while `Position` and the `width`/`height` bounds are non-negative. One translation by `(−min_x, −min_y)` normalizes everything — cells, entrance, transition positions, and the cells the canonical edge keys are built from — and the level sizes to the resulting bounding box. The axes already agree — OPD's y increases downward (screen convention), exactly osrlib's documented `y increasing south` (`dungeon.py:63`) — so translation is the *only* transform, no flip; this is stated because no internal-consistency test can catch a mirrored import, only the milestone's eyeball against the generator's own rendering can. Sixth, **the entrance is a hard format invariant and a second one is the backdoor**: every export in the corpus carries a `type: 3` door at exactly `(0, 0)` (145/145, and the sample), a second type-3 being `addBackdoor()`'s alternative entrance. The editor has one `entrance: Position | None`, so the origin door becomes the entrance and any second one is noted rather than silently dropped. Seventh, **the format is stable across every shipped version and has no seed**: eight top-level keys, all required, unchanged from 1.1.1 through the current 1.2.7 (read out of the live bundle's `getData()` return literal, which is exhaustive). Both third-party TypeScript types circulating in the wild declare a `seed` field; **no export at any version has one** — rendall's navigator keeps a sidecar `seeds.json` precisely because of that absence. `ending` and door types 7/8/9 are the only real additions across the range. So version tolerance is structural: parse by key presence, never by version string, and map an unknown door type to a plain door with a note, which is what forward compatibility costs here. Eighth, **licensing is clear but the committed fixtures are ours regardless**. Watabou's stated terms are explicitly permissive — "You can use images created by the generator as you like: copy, modify, include in your commercial rpg adventures etc. Attribution is appreciated, but not required" ([itch.io](https://watabou.itch.io/one-page-dungeon), restated at [the Procgen Arcana FAQ](https://watabou.github.io/faq.html)) — the author has publicly encouraged third-party tools that read the JSON and refuses to rename fields because it "would break compatibility with applications supporting the current format", and a file format is not copyrightable subject matter in the first place. Two frictions nonetheless point the same way: the permission wording says "images" and "maps" and never "data" or "JSON", the author himself calls it an "informal license", and — decisively for testing — no single real export contains all ten door types, a rotunda, and a backdoor. So the committed corpus is **hand-authored synthetic OPD-shaped JSON**: original material under `AGENTS.md`'s fixture fence (`AGENTS.md:67`), unambiguously ours, and strictly better coverage. The generator's own code is genuinely closed and is never vendored. Ninth, **the converter ships bundled, and the seam is unharmed** — see the packaging decision below, settled by owner decision and already reflected in the spec.

## Packaging decision

The spec's prior sentence made "converters beyond import-from-project are separate installable packages" an absolute. Phase 8 **bundles** the OPD converter into osr-editor instead, and the spec's future-extensions bullet is amended alongside this plan to state a bar rather than an absolute (`spec.md:243`, the phase 7 precedent of amendments landing with the plan that argues them). The reasoning: the seam's honesty is already secured by dogfooding — `pyproject.toml:44-49` registers the built-in import-from-project importer through the same public entry-point group any third party uses, with the comment saying exactly why — so a second distribution buys no architectural proof it doesn't already have. Against that, it would cost a second release pipeline in phase 10, a version-compatibility surface against `ImportedGeometry`, and a user who installs osr-editor and doesn't get the feature. The converter itself is a pure stdlib JSON reader with no new dependencies. The bar as amended: **a format bundles when it is broadly useful, permissively licensed, and parseable with no new dependency; everything else is third-party** — and the entry-point group stays public either way, so the third-party path is exercised rather than merely promised.

## Scope

In scope:

- `importers/` becomes a package — `__init__.py` (protocol, payload, discovery), `project.py` (import-from-project, moved), `watabou.py` (the new converter); the entry-point target in `pyproject.toml` moves with `ProjectImporter`
- The OPD reader: structural parse and validation, the ten-door-type mapping, coordinate normalization, floor-set→edge-set conversion, notes→keyed areas, the entrance and the type-8 transition, and a `notes` entry for every guess, drop, and repair
- Metadata adoption — the phase 2 deferral: the import dialog's title/story adoption controls over the already-complete `ImportedGeometry.title`/`description` fields
- Hand-authored synthetic OPD fixtures (a nominal dungeon and a torture case covering all ten door types, a rotunda, a backdoor, negative coordinates, and an unknown door type) plus their suites
- Frontend: adoption UX, the generic source-path placeholder, importer-notes rendering already in place
- README, CHANGELOG, and the spec amendments (the bundling bar; the "future work" sentence at `spec.md:114` retires)

Out of scope (each with where it goes): walk mode (phase 9). Docs site and release engineering (phase 10) — including any published guide to writing a third-party importer, which belongs with the docs site and is explicitly not a phase 8 deliverable. A second external format (Dungeon Scrawl, donjon, Dungeondraft) — the seam is proven by two implementations over genuinely different sources, and a third earns its way in on demand, which is the seam's whole point. Round-room geometry — a rotunda imports as its bounding square of floor cells with a note, because the editor's grid has square cells and inventing a circle-approximation vocabulary for one source format's flag is exactly the format-specific creep the seam exists to prevent. Columns and water — no editor model exists (`ImportedArea` carries id, name, description, and cells, and features are content ops the payload deliberately does not reach), so both are dropped with a counted note; wiring them to phase 3's feature vocabulary would mean the payload grows content, which is a `GeometryImporter` redesign, not an importer. Multi-level OPD import — the format is single-level by construction (the `multi-level` tag emits one type-8 door into space that is never generated or exported), so the type-8 transition carries a dangling target the author either keeps through the dialog's existing keep-unresolved checkbox or lets drop, and the phase 2 `transition_unpaired` lint is the author's to-do list — one with a deadline, because publish's clean-validation gate refuses a target that still dangles (work item 2). Any write path back to OPD — import is one-way. Live fetch from the generator's URL — the importer reads a local file the user exported, and no editor feature reaches the network for geometry.

## Work items

### 1. The importers package split

`importers.py` becomes `importers/`: `__init__.py` keeps `ENTRY_POINT_GROUP`, `GeometryImporter`, `ImportedArea`, `ImportedLevel`, `ImportedGeometry`, and `discover_importers` as its own definitions; `project.py` takes `ProjectImporter` and the `_imported_level`/`_next_free_key` helpers; `watabou.py` is new. The entry point moves to `project = "osreditor.importers.project:ProjectImporter"` and every call site updates — a real move, not a compatibility re-export (`AGENTS.md:48`). `__init__.py`'s module docstring keeps the seam's charter and drops the phase 2 sentence deferring adoption UX, which this phase closes.

### 2. The OPD reader

`watabou.py`, `format_id = "watabou-opd"`, `label = "Watabou One Page Dungeon (JSON)"` — nominative naming, describing the format interoperated with, never branding the feature (research fact eight; the name also predates the generator by a decade, being the One Page Dungeon Contest's).

- **`sniff`** stays presence-level and bounded, per the protocol's own contract ("never loads"): the path is a file with a `.json` suffix whose bounded head-read carries the OPD key signature (`"rects"` and `"doors"`). The bound is 64 KB, and the number is load-bearing: `"doors"` follows the entire `rects` array (byte 4,464 in an ordinary 147-rect export) and moves right as rect count grows, so a small head would false-negative on big dungeons — while every real export observed stays under 10 KB, so 64 KB clears the signature with an order of magnitude to spare and still costs one short read on a huge or binary file. It never parses the document.
- **`load`** parses and validates structurally, by key presence and never by `version` string (research fact seven). Anything unloadable — unreadable path, malformed JSON, a missing required key, a non-array `rects`, or a `rects` array whose union is no floor cell at all — raises `ImportSourceInvalidError` with a human message, the protocol's stated failure mode. The floorless case is named because it is the one shape that would otherwise fail in the wrong layer: an empty floor set makes the bounding box 0×0, `ImportedLevel` requires `width`/`height ≥ 1`, and a pydantic validation error inside `load` surfaces as a 500 rather than the protocol's 4xx. The `version` string is recorded in a `notes` entry so an author who later hits a conversion oddity knows what produced the file.
- **Floor and normalization**: the floor-cell set is the union of every rect's half-open span (`x <= i < x + w`), translated by `(−min_x, −min_y)`; `width`/`height` are the resulting bounding box (research facts two and five). Rects that overlap — not observed, but not guaranteed — union harmlessly, since the target is a set.
- **Edges**: for every orthogonally adjacent pair of floor cells, an `Edge(kind=OPEN)` under osrlib's canonical key; then every door overrides its one edge per the fact-three table. Doors are matched to their edge by `(x, y)` and `dir`; a door whose `dir` neighbour is not floor and whose type is neither 3 nor 8 is a malformed record, dropped with a note rather than crashing the import. Two doors sharing a cell (observed once in 145 files) resolve first-wins with a note — a real occurrence the reader must not assume away. Two doors sharing an *edge* without sharing a cell — each sitting in the other's `dir` neighbour, never observed but not excluded by anything — resolve the same way, first-wins with a note, because a dict override that silently last-wins is an accident, not a judgment call.
- **Entrance and transitions**: the type-3 door at the origin becomes `entrance` (fact six); a second type-3 is noted with its position, not dropped silently, so the author can place a second stair by hand. A file with *no* origin type-3 — the invariant held 149/149, but generator output is not the only OPD-shaped JSON in the world; this plan's own hand-authored fixtures prove the class exists — degrades to `entrance = None` with a note, never a failure: the payload's `entrance` is already optional, the dialog already skips `SetEntrance` on null, and the `entrance_missing` finding carries it from there. A type-8 door becomes a `TransitionSpec(kind="stairs_down", position=<the door cell>)` whose destination is fabricated whole, because the spec requires a full one — `to_dungeon_id`, `to_level_number`, `to_position`, `to_facing` — the source has data for none of them, and the importer cannot know even the destination level number, which the dialog chooses after load. The fabrication is pinned so the behavior is deterministic: `to_dungeon_id = ""` (matches no real dungeon, so the dialog's resolution test fails by construction rather than by luck), `to_level_number = 2`, `to_position = (0, 0)`, `to_facing` from the door's `dir`, all named in a note. A dangling target is legitimate under the op's own rule, which the existing importer already documents ("The target may dangle — that stays", `importers.py:276`) — but the plan owes the whole downstream truth: the dialog treats an unresolvable transition as *drop-by-default*, kept only when the author checks its keep-unresolved box (`import-mapping.ts:152-162`); kept, `transition_unpaired` (a warning) carries it while editing; and publish requires the clean validation tier (`app.py:1056`), whose `validate_adventure` errors on an unknown target — so a kept stair must be resolved into a real level or deleted before publish. The to-do list has a deadline, and one of the three fresh exports carries a type-8, so the milestone dungeon can genuinely hit it.
- **Keyed areas**: each note keys the one rect containing its `pos`, by `ref` and never by array index (fact four): `ImportedArea(id=ref, name="", description=text, cells=<that rect's translated cells>)`. `name` stays empty because OPD has no room-name field and inventing one from prose is editorializing. A note whose `pos` lands in no rect, or in a rect another note already claimed, is dropped with a note naming the ref. A duplicate or empty `ref` renames to the next free key with a note — `ProjectImporter`'s own rule (`importers.py:259-263`) — because `CreateArea` rejects a duplicate `area_id` at apply and the batch is atomic, so a payload carrying two areas with one id 422s the whole import with no path forward, exactly the failure load-normalization exists to prevent. Refs are unique in every observed export; the reader must not assume it.
- **Dropped with a counted note**, each in its own sentence: `columns` and `water` (no model), `rotunda` (imported as its bounding square), and `ending` (the generator's deepest room, no model). Every one of these is a `notes` entry, because "each importer owns its format's judgment calls … flagging what it guessed" is the seam's contract (`spec.md:112`).
- The module docstring credits Watabou and names the format and the terms it was read under — attribution is appreciated and not required, and it costs nothing (research fact eight).

### 3. Metadata adoption — the phase 2 deferral

`ImportedGeometry.title`/`description` are already on the payload and already populated by `ProjectImporter`; only the UX was deferred, and to this converter by name (`importers.py:16-18`, `phase-2-plan.md:95`). The OPD reader maps `title` → `title` and `story` → `description`. The dialog grows two independent adoption checkboxes, shown only when the loaded payload actually carries the field and the value differs from the project's current one, defaulting to **off** — an import is a geometry gesture, and silently rewriting the adventure's name is not what the author asked for. Adopted values ride the same op batch as the geometry (`SetAdventureField` name/description), so adoption is one undo step with the map, translates in forge-backed projects through the existing area/adventure override paths, and never becomes a second commit that can half-fail.

### 4. Frontend

- The adoption checkboxes and their gating (item 3), rendered in the existing preview section beside the importer notes the dialog already lists (`import-dialog.tsx:250-254`).
- The source-path placeholder generalizes from `/absolute/path/to/project` to cover a file, since the dialog's free-text path already accepts one and `sniff` is what disambiguates — no picker rework, and the multi-importer match list already exists (`import-dialog.tsx:205-225`).
- No new store or API surface: `sniffImporters` and `loadGeometry` are unchanged, and the batch the dialog builds grows only the two optional adventure-field ops.

### 5. Registration and packaging

The bundling decision above: a second entry point, `watabou-opd = "osreditor.importers.watabou:OPDImporter"`, in the same group, with the existing comment extended to record the bar a bundled format meets. No new dependency. `discover_importers`' duplicate-`format_id` and broken-entry-point guards already cover a third-party package that ships the same format, and their tests grow a case proving a third-party registration coexists with both built-ins.

### 6. Fixtures and tests

- **Fixtures** are hand-authored synthetic OPD-shaped JSON under `tests/assets/opd/` with a README recording provenance and the fact that they are original material, not generator output (research fact eight): `nominal.json` (a few rooms, corridors, junctions, doors, notes, an entrance) and `torture.json` (all ten door types, a rotunda, a backdoor, a type-8 stairs-down, negative coordinates, a note landing in no rect, a duplicate note ref, two doors on one cell, two doors sharing one edge from opposite cells, an unknown door type, and a `version` string from outside the known set). The real 1.2.7 exports this plan was validated against stay out of the repository and are named in the README as local-validation-only.
- **pytest**: `sniff` accepts the fixtures, accepts a large file whose `"doors"` key sits beyond a small head but inside the 64 KB bound, and rejects a directory, a non-JSON file, and a JSON file that isn't OPD; `load` goldens for both fixtures over the whole payload; the door-mapping table case by case, the shared-cell and shared-edge first-wins rules included; coordinate normalization against negative inputs; the floor→edge conversion including that every emitted key is canonical and every referenced cell is in bounds; notes keyed by `ref` under a shuffled array order, with the duplicate-ref rename proven to survive the batch (no two areas share an id); an entranceless variant importing with `entrance = None` and a note; the unknown-door-type and malformed-record paths producing notes rather than raising; `ImportSourceInvalidError` on each unloadable shape, the floorless `rects` array included. Registry tests grow the coexistence case.
- **Round-trip**: an imported torture fixture applies as a batch and the resulting document is byte-stable under canonical serialization and loads against the pinned osrlib, joining the existing fixture discipline.
- **vitest**: adoption-checkbox gating (absent when the field is absent or unchanged, off by default), and the batch composition including the adventure-field ops exactly when adopted.
- **e2e (Playwright)**: import the torture fixture into a blank project, adopt title and story, check the keep-unresolved box on the type-8 stair — the dialog drops an unresolvable transition by default, so the finding exists only because the test kept it, same as an author would — see the map draw and the importer notes render, and assert the *complete* expected finding list for the fixture, `transition_unpaired` on the stair among them, so no regression hides behind an under-specified assertion. The honest result, asserted rather than worked around.

### 7. Docs and amendments

README gains the OPD import line and CHANGELOG gains the phase bullet, both in the implementation PR. The spec amendments already landed with this plan (the phase 7 precedent): `spec.md:114` now names phase 8 as the converter's home and records the door-cell/door-edge impedance of research fact one, and `spec.md:243`'s future-extensions bullet carries the bundling bar and the formats still unbuilt. The roadmap renumbering landed with them — walk mode to phase 9, documentation and release to phase 10, across `spec.md`, `AGENTS.md:71`, and every prior phase plan's out-of-scope list, so no deferral points at a phase number that moved. What remains for the implementation PR is `phase-2-plan.md:95`'s "that converter is an installable package" aside, which the bundling decision supersedes and which retires when the deferral it records is closed.

## Sequencing

1. The `importers/` package split with the entry-point move; existing suites green unchanged.
2. Hand-authored fixtures and their README.
3. The reader: parse and validate, normalization, floor→edges, doors, entrance and transition, areas, notes — with pytest goldens as built.
4. Registration and the registry coexistence test.
5. Metadata adoption: payload wiring, dialog controls, batch composition; vitest.
6. The Playwright import milestone; the byte-stability round-trip.
7. README, CHANGELOG, and the retirement of `phase-2-plan.md:95`'s superseded aside (the spec amendments and renumbering landed with this plan — work item 7); the manual milestone half — a freshly generated dungeon imported, its map eyeballed against the generator's own rendering (the orientation check no internal test can make), any type-8 stair resolved or dropped ahead of the publish gate, then stocked, published, and played in osr-web — recorded in the PR, the established pattern.

## Definition of done

- The full gauntlet stays green on both toolchains with zero network in CI; the typegen drift gate passes with the injection list still `[ApiError]`.
- The milestone works end to end: deterministically in Playwright over a committed fixture, and by hand with a freshly generated dungeon imported, its map matching the generator's rendering by eye, stocked, published, and played in osr-web, recorded in the PR.
- The seam took no format-specific damage: `GeometryImporter` and `ImportedGeometry` are unchanged, no editor code outside `watabou.py` knows what OPD is, and a third-party importer registering alongside both built-ins is proven by test.
- Every phase 2 deferral to this converter is closed and traceable — the adoption UX exists, and `importers.py`'s deferral docstring is gone rather than reworded.
- The importer is honest about its judgment calls: every guess, drop, and repair in the fact-three table and the dropped-features list is a `notes` entry the dialog renders, and the torture fixture proves each one.
- No licensing fence is crossed: every committed fixture is hand-authored original material, no generator code is vendored, the format is named nominatively, and Watabou is credited in the module docstring and README.
- An unknown door type, an out-of-range `version` string, and a file with no origin entrance import successfully with notes — forward compatibility, and robustness against producers other than the generator, are proven by test, not assumed.
